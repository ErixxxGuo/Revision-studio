# Revision Studio 技术说明

本文面向需要修改、审查或恢复项目代码的开发者。普通用户请先阅读根目录的 [`README.md`](../README.md)。

## 1. 运行模型

项目是一个无框架、无运行时依赖的原生 JavaScript 单页应用。

- `../revision-studio.html` 是唯一运行入口，样式、脚本和内置 0478 资料均已内嵌。
- `../serve.py` 使用 Python 标准库提供本机页面、模型请求代理和响应缓存。
- 浏览器负责界面、状态、PDF 读取、公式排版和本地存储。
- DeepSeek 或其他 OpenAI 兼容接口负责考纲识别、卡片生成和试题解析。
- 项目没有业务服务端数据库，也不在本地运行大模型。

当前目录保存源码快照和维护资料，不会在运行时被 HTML 自动加载。

## 2. 目录职责

```text
项目根目录/
├── README.md                    面向使用者的说明
├── revision-studio.html         实际运行入口

└── workspace/
    ├── TECHNICAL.md             本文
    ├── AGENTS.md                AI 修改约束
    ├── data/builtin.json        内置资料源文件
    └── src/

        ├── css/                 样式
        └── js/                  业务逻辑
```

不要仅修改 `src/` 后假设运行页面会改变。构建工具已移除，当前 HTML 是独立交付物。

## 3. 启动与代理

在项目根目录运行：

```powershell
python -B serve.py
```

默认参数：

| 项目 | 默认值 |
|---|---|
| 地址 | `127.0.0.1:8787` |
| 页面 | `/revision-studio.html` |
| 上游 | `https://api.deepseek.com` |
| 请求体上限 | 4 MB |
| 上游超时 | 600 秒 |
| 磁盘缓存 | `.cache/`，最多 4000 个文件 |

`serve.py` 只接受 `localhost` 或 `127.0.0.1` 来源，用于降低 DNS 重绑定和跨站调用风险。它只提供运行 HTML，不暴露整个目录。

可用环境变量：

| 变量 | 作用 |
|---|---|
| `DEEPSEEK_API_KEY` | 页面未填写 Key 时由代理使用 |
| `UPSTREAM` | 替换 OpenAI 兼容上游地址 |
| `PORT` | 替换本地端口 |
| `NO_BROWSER=1` | 不自动打开浏览器 |
| `NO_CACHE=1` | 禁用响应缓存 |

不要把 API Key 写入源码、Markdown 或 Git 跟踪文件。

## 4. 前端结构

页面由三个主要状态组成：

- `home`：科目首页和入口。
- `subject`：逐条复习卡片。
- `papers`：试题导入、解析和历史。

公共弹窗统一位于 `#modal`，通过 `showBox()` 切换面板。页面没有前端路由，历史状态由内存中的视图变量控制。

`src/js/` 使用普通 script 拼接方式，所有文件和函数共享全局作用域。不要直接加入 ES module 的 `import/export`，否则会改变最终单文件运行方式。

## 5. 考纲识别与生成

主要流程：

1. PDF.js 提取文字层，或将粘贴文本按约 3000 字分页。
2. 可选手工页码范围；否则由模型定位包含考点的正文页。
3. 按约 9000 字切分窗口，相邻窗口保留一页重叠。
4. 模型逐窗提取考点，程序按章节和原始编号合并。
5. 程序扫描原文编号，并与模型统计、提取结果三方核对。
6. 对缺失编号进行定向补读。
7. 用户检查大纲后，生成阶段再进行最后一次缺口补全。
8. 卡片按章节和长度分批生成，非本地模型最多三路并发。
9. 每批完成后立即写入浏览器存储，允许停止和续传。

生成提示词要求输出严格 JSON。模型返回的重点词必须能在考点原文中找到，否则丢弃；图示只接受预定义结构，由本地 SVG 渲染器绘制。

## 6. 试题解析

试题工作区支持图片和 PDF。PDF 页面在浏览器中渲染为图片后送入模型，避免把不可靠的 PDF 文字层当作题干。

流程：

1. 识别题目和可选 MarkScheme。
2. 用户核对题号、公式、答案配对和不清晰内容。
3. 按明确的小题编号建立 `parts`。
4. 调用模型生成英文答案、中文解释、步骤、得分点和易错点。
5. 若关联考纲，发送完整考点列表，并按语义关联实际考点 ID。
6. 整题完成后保存到历史，允许停止和继续解析。

约束：

- 不得静默覆盖已有答案。
- 小题缺失时保留原结果，不把不完整结果当成成功。
- 评分代码只采用 MarkScheme 中实际出现的代码。
- 高光只处理普通文本节点，跳过公式、代码和标签。
- 原题图片保存在 IndexedDB `revstudio-originals`。
- JSON 备份不包含原题图片和 API Key。

## 7. 数据模型与兼容性

主要 localStorage 键：

```text
revstudio-proto-v1
```

核心状态 `S` 包含：

- `subs`：用户科目
- `cur`、`idx`：当前科目和考点
- `prog`：复习进度
- `fold`、`pos`：侧栏与阅读位置
- `cfg`：模型配置
- `papers`：试题文字记录
- `use`：调用量和费用
- `paperSplit`：试题双栏比例

题目原图使用 IndexedDB 数据库 `revstudio-originals`。

存储按浏览器 origin 隔离。通过 `http://localhost:8787` 使用旧页面和新页面时，路径变化通常不影响 localStorage 和 IndexedDB；直接通过 `file://` 打开时，浏览器可能按文件路径隔离存储。

修改存储键、数据结构或迁移逻辑前必须提供兼容和备份方案。

## 8. 修改工作流

1. 确认任务只涉及运行入口、源码或文档中的哪一层。
2. 修改前检查工作树，避免覆盖用户未提交文件。
3. 如果修改 `src/`，同时评估根目录 HTML 是否需要同步；两者不会自动构建。
4. 不要在未备份当前 HTML 的情况下用历史版本整体覆盖。
5. 修改存储或接口协议时，保留旧数据读取路径。
6. 测试临时文件只能放在 `.ai-tmp/`，不能混入用户资料。

## 9. 验证清单

当前仓库没有自带自动测试。改动后至少完成与风险相称的检查：

- `git diff --check`：检查空白和补丁格式。
- 对修改的 JavaScript 做语法检查。
- 用 `python -B serve.py` 启动服务。
- 请求 `http://localhost:8787/revision-studio.html`，确认返回 200 且页面可打开。
- 修改卡片、导入、存储或试题流程时，分别验证刷新、重试、停止和窄屏布局。
- 不要用真实 API Key 或真实用户资料做自动化测试。
- 未执行的测试必须明确写成“未验证”。

## 10. 安全边界

- HTML 文本必须转义后再插入页面。
- 公式交给 KaTeX，并关闭不受信任的扩展。
- 重点词高光不得修改公式或属性。
- 模型输出不是可信代码，必须经过 JSON 解析和数据清洗。
- `serve.py` 只监听本机，不接受任意外部来源。
- `.cache/` 可能包含用户发送给模型的内容，不应公开或提交。
- `.ai-tmp/` 只用于短生命周期测试文件。
