# Revision Studio 工程说明

这份文档写给不熟悉本工程的人。看完后可以自己改内容、重新装订、跑自检。

---

## 1. 项目背景与目标

Revision Studio 是一个基于 IGCSE 考纲的复习网站，作用是把考纲里的每一条学习目标（learning objective）整理成可以逐条翻阅的复习卡片。成品是单个网页文件 `revision-studio.html`，双击即可打开，不需要安装。科目数据和复习进度保存在浏览器本地，不会上传；联网只用于调用 AI 接口和加载公式渲染组件。

项目内置一份已经完成的 Computer Science 0478 复习资料：Cambridge IGCSE Computer Science 0478 的全部 102 条考点，分 10 个主题、24 个章节，每条都配有手写的要点讲解、重点词高亮，以及流程图、表格或示意图。打开就能直接复习，也可以当作效果示例。

除内置资料外，用户可以用同一套流程处理自己的考纲：上传 PDF、TXT、Markdown，或直接粘贴文本，再交给 DeepSeek 分析。分析分几步走：先通读并定位正文页，再分段提取考点，与原文逐条核对条数、补读遗漏，最后按考点生成卡片——卡片会画出重点词，给出几条直击考点的要点，并配一张最简的图表。使用前需要填 DeepSeek API Key，或运行本地代理 `serve.py` 转发请求；花费按官方定价用人民币估算，并在生成过程中实时显示。

项目的目标是省去手工整理考纲和做笔记的时间，让复习变成能按条推进、能看到进度的事；生成的卡片也可以导出分享给同学。

## 2. 两套文件，用途不同

| 文件 / 目录 | 是什么 | 能不能手改 |
|---|---|---|
| `revision-studio.html` | 装订好的成品。双击即可用；发给同学、交给老师的也是它 | 不要手改。改了它，下次装订会被覆盖，自检也会报错 |
| `src/`、`data/` | 散件，也就是源码。改内容都在这里改 | 改这里 |
| `build.py` | 装订脚本，把散件拼回成品 | 不用动 |
| `check.py` | 自检脚本，检查装订是否一致、结构是否损坏、文案是否跑偏 | 不用动 |
| `baseline/revision-studio.html` | 金标准，拆分之前的那一份，一个字节都没改，用来对照 | 不要动 |
| `serve.py` | 本地代理，转发 AI 请求并做磁盘缓存 | 不用动 |
| `.cache/` | `serve.py` 的接口缓存，删了不影响使用 | 可以删 |

三者的分工：成品给用户看，散件用来修改，金标准用来对照。

## 4. 日常怎么用（三条命令）

```bat
python build.py        :: 改完散件后，装订成 revision-studio.html
python check.py        :: 自检（默认会顺手做一次渲染冒烟测试）
python build.py --check :: 只看散件和成品是否一致，不写文件
```

正确的循环是：

**改散件 → `python build.py` → `python check.py`**

`check.py` 最后会打印"结果：全部通过"或者列出不通过项。只要有不通过项，就不要把成品发出去。

装订脚本还有两个用法：

```bat
python build.py --out 临时文件.html                    :: 装订到别处，不碰成品
python build.py --against baseline\revision-studio.html :: 和指定文件逐字节比对
```

## 6. 提示词是拆开存放的

`src/js/11-prompts/` 里是 6 个文件，拼起来正好是原来的提示词模块：

| 文件 | 内容 |
|---|---|
| `00-head.js` | 模块头注释，不是提示词 |
| `10-sys.js` | `SYS`：给每个考点写卡片 |
| `20-loc.js` | `LOC`：通读全文，定位正文页并数条数 |
| `30-ext.js` | `EXT_SYS`：分段提取考点（逐字复制） |
| `40-repair.js` | `REPAIR_SYS`：补读缺的编号 |
| `50-fill.js` | `FILL_SYS`：生成前补全缺失考点 |

改提示词时注意两件事（交接文档里踩过坑）：

1. 这些字符串是单引号拼接的，换行要写成 `\n`（源码里就是两个字符），别把一整行拆成真正的换行，否则拼出来的提示词会变形。
2. 提示词里的反斜杠（比如 `\\ce`、`\\frac`）在 JS 源码里要写两个，写错会让公式变成控制字符。改完跑 `python check.py` 再自己看一遍。

顺序由文件名决定：`00 → 10 → 20 → 30 → 40 → 50`。不要改这些文件名。

---

## 7. 三条约定

1. 顺序就是文件名里的编号。
   CSS 尤其是这样：这个项目的样式靠顺序覆盖，`01 → 11` 的顺序就是层叠顺序。把文件改名（比如 `05-notes.css` 改成 `15-notes.css`），样式优先级就变了。`check.py` 会检查编号连不连续。

2. 改了散件必须重新装订。
   否则成品还是旧的，`check.py` 第一条就会报"不一致"。

3. 不要手改成品，也不要动 `baseline/`。
   成品改了会被下次装订覆盖；金标准改了，自检里"文案只报新增"的对照就失效了。

另外：`python tools/split.py` 是危险命令。它会用金标准重新生成全部散件，你在散件里做过的所有修改都会丢失。所以脚本默认拒绝在有散件时运行，真要重来必须写 `python tools/split.py --force`。

## 8. 自检脚本查什么、不查什么

**查（不通过就报错）**

| 项 | 说明 |
|---|---|
| 装订一致性 | `src/` 拼出来的内容与成品逐字节相同；也检查散件能不能拼出完整页面 |
| 散件清单 | CSS 11 个、页面结构 11 个、JS 25 项、提示词 6 个，编号连续，文件名和文件内的模块编号对得上 |
| 数据合法 | `data/builtin.json` 是合法 JSON |
| 页面结构 | id 有没有重复；`$('…')` 引用的 id 存不存在；`for` / `aria-labelledby` / `aria-controls` 指向的 id 存不存在；`<use href="#…">` 引用的图形存不存在；CSS 花括号是否配对 |
| 脚本语法 | 30 个 JS 文件的括号、引号配对；本机装了 node 会自动加做 `node --check` |
| 渲染冒烟 | 用本机 Edge/Chrome 的无头模式打开成品，确认首页真的渲染出内容、侧栏真的列出了科目（用临时配置目录，不碰你的浏览器数据；加 `--no-browser` 可跳过） |
| 本地代理 | `serve.py` 找到的页面就是当前这个成品（只看它选了哪个文件，不会真的启动服务） |
| 文案体检 | 半角标点紧邻汉字、`「」`、警告符号/emoji；与金标准对比，只报新增 |

**不查（这些还得靠人看）**

- 没有装 node，就没有权威的 JS 语法检查。括号配对和"页面能不能跑起来"能挡住绝大多数错误，但像 `var x = ;` 这种错的定位不如 `node --check` 精确。装了 Node.js 后会自动启用。
- 样式对不对、好不好看：冒烟测试只确认"渲染出来了"，不比较像素。
- 内置考纲的内容是否正确（内容质量只能人工核对）。
- 真实 AI 接口的行为（要用 `serve.py` 跑真机才算）。

## 10. 以后想更省心

- 装 Git（版本管理）：每次改完存一次，改坏了随时回到上一个版本。在此之前，至少每周把整个文件夹复制一份带日期的备份。
- 装 Node.js：`check.py` 会自动启用 `node --check`，语法检查更准更细。
- 想调整样式顺序（比如把 `08-responsive.css` 挪到最后）时，先想清楚它会影响所有手机适配，改完一定要用手机宽度看一眼。
