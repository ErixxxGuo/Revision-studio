# CSS 顺序说明（改样式前先读）

这个目录里的文件按**文件名顺序**拼接进成品的 `<style>`，
**顺序就是层叠顺序**：靠后的规则会盖掉靠前的规则。

| 顺序 | 文件 | 作用 |
|---|---|---|
| 01 | `01-content.css` | 内置 0478 手写内容的样式 |
| 02 | `02-base.css` | 设计变量（浅色 / 深色）、重置、全局元素 |
| 03 | `03-sidebar.css` | 侧栏、科目与章节列表、更多菜单、拖动手柄 |
| 04 | `04-card.css` | 页头、复习卡片、翻页、底部导航 |
| 05 | `05-notes.css` | 右侧笔记、考纲注释、图示、Markdown 与公式 |
| 06 | `06-genbar.css` | 生成进度条 |
| 07 | `07-modal.css` | 弹窗、表单、按钮 |
| 08 | `08-responsive.css` | **窄屏（手机）适配** |
| 09 | `09-wizard.css` | 新建科目向导 |
| 10 | `10-home.css` | 首页 |
| 11 | `11-share.css` | 分享 / 导入面板 |

## 两个坑

1. **`08-responsive.css` 在中间，不在最后。**
   它后面还有 09 / 10 / 11 三个文件。也就是说，向导、首页、分享面板里
   如果写了和手机适配冲突的规则，会盖掉 `08` 里的媒体查询。
   历史上就出过事故：`#sidebar{position:relative}` 把手机端的 `position:fixed` 盖掉，
   内容被挤成一条窄缝。**改完样式一定要用手机宽度看一眼。**

2. **不要改文件名。** 前缀 `01`…`11` 决定了顺序，改名等于改样式优先级。
   `python check.py` 会检查编号是否连续、文件名前缀是否和文件内的模块编号一致。

## 怎么加新样式

- 优先加在**对应组件**的文件里（改侧栏就改 `03`，改首页就改 `10`）。
- 确实要新增文件时，编号往后排（例如 `12-xxx.css`），**不要插在中间**，否则后面全部挪位。
- 加完跑 `python build.py` 再跑 `python check.py`。

> 本文件是说明文档，扩展名不是 `.css`，装订脚本会自动忽略它，不会进入成品。
